# 光影大亨 v0.3：可玩像素重製

## Outcome and phase

Playable rebuild / release。使用者已明確授權安裝 guangyuspace/codex-gamestudio-skill、重製現有遊戲（包括貼圖及地圖），並更新目前 GitHub Pages。這取代先前「只交設計、待確認才實裝」的交付邊界。

玩家可以安排營運，觀察有階梯高度的影院自行運作，點選區域查看狀態；突發時選擇員工或親自救場，再用盈利升級、買斷及管理第二店。新介面以影院畫面為第一焦點，經營摘要及完整管理頁承接操作。

## Shipped scope

- 現代香港、32-bit 年代像素風格；32×34 格地圖，沒有獨立候場區及長椅。
- 兩個 13×17 格影廳，起始 48 / 40 席；8 排座席由 0.00m 升到 2.10m。每相鄰兩排兩級，各 0.15m。
- 影廳淨高 5.20m，銀幕上下邊 +1.00 / +4.30m；側門連接零高度前廳，中央樓梯接各排及後排通道。
- 4 格主通道、3 格橫通道；售票、小食、後勤、洗手間獨立分區。
- 模組化地板、牆、階梯、家具、角色及電影投映；沒有以單張背景圖冒充可行走地圖。
- 16 款設施來源、四方向兩姿勢的客人與職員、20 款原創戲仿電影海報。地圖不使用候場長椅，來源圖集保留該款作素材相容。
- 地圖點選、區域按鈕、拖曳、縮放、鍵盤移動／縮放；手機可用按鈕及觸控拖曳。
- 初始日間營運、排片、六類客群、分帳、定價、人手、小食供貨、事件、小遊戲、日結、貸款、物業及兩店直接管理沿用既有確定性規則。
- 座位升級每廳增加一列 8 席並實際繪製；小食及裝修升級會增設相應設備、燈箱或盆栽。
- 可選開場、操作、事件及散場提示音；預設關閉，由使用者手動啟用。

特別格式及完整影展仍屬後續內容，沒有加入新收費、廣告或後端。這次不轉換瀏覽器執行引擎；Godot 來源仍保留，技術邊界沿用既有 ADR。

## Owners and contracts

- `engine.mjs`：財務、日期、需求、排片、事件、投資及 v2 存檔，仍為唯一狀態權威。
- `game.mjs`：管理介面與玩家命令；不把畫面角色數目當作財務入場人次。
- `world.mjs`：座位容量對應、底座貼合、地形高度及導航。0.5 格導航，家具底座另留 0.18 格邊距；每步升降上限 0.15m。
- `scene.mjs`：像素材質與幾何，按深度快取為緊密邊界的透明圖層；角色可插入圖層之間。
- `render.mjs`：相機、動態代表性客流、已入座人群、員工、維修標記及電影投映。
- `assets.mjs`：所有素材預載，綠幕只在載入時於記憶體轉透明。來源 PNG 不被改寫。
- `src/assets/cinema/runtime/manifest.json`：房間、門、牆、高台、座椅、排隊、裁切及錨點的版本化預設。

保存 `lumen-cinema-v2` 鍵、`lumen-cinema-save` type 及 schema version 2；不清除或自動覆寫既有存檔。舊版本實際產生的 fixture 驗證現金、物業、兩店及擴充座位保持不變。

## Verification and release

27 項 Node 測試（17 模擬、1 DOM 整合、9 新地圖／素材／相容測試）通過。真實 Chromium 完成 18 項流程檢查：新開局、地圖、相機、20 部電影、自動營業、舊存檔、可視升級、定價、三種小遊戲、日結、離線操作、三種觸控尺寸及素材載入失敗。

本機 Chromium 1440×1000：暖機繪製 CPU p95 約 10.5ms；初次圖層建立約 401ms，快取約 58MiB／分店。此數值是該測試環境的 CPU 指標，不當作手機 GPU 或實機幀率證明。主目標為電腦瀏覽器，手機驗證為模擬觸控尺寸 390×844、720×1280、1080×2400。

證據：`production/verification/v0.3/browser.json`、`docs/screenshots/`。真人長期經濟節奏、不同手機實機及完整聲音體驗仍待試玩。

Pages 發佈由既有 workflow 先執行測試，再打包 `dist/pages`，不依賴 symlink 或外部 CDN。`version.json` 帶版本及來源 commit；回退方式是 revert 本輪 release commit，重新使用相同 workflow 部署。舊存檔格式不變，因此回退不需要刪檔或回復資料庫。

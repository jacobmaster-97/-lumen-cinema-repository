# 戲院經營遊戲：構思草案

狀態：21 項核心選擇已記錄，待確認原型範圍；尚未開始原型。
暫名：戲院經營遊戲；正式名稱待定。
使用流程：Codex Game Studio / cgs-brainstorm。

## 使用者提出的方向

- 美術：32-bit 年代風格的像素美術，已選擇斜角俯視／等角視角；像素密度、色盤及參考作品待確認。「32bits」暫視為視覺風格描述，並非執行檔架構或色彩格式規格。
- 平台與背景：首個原型為電腦瀏覽器遊戲，滑鼠操作，世界背景為現代香港。
- 類型：以模擬經營為主，設定好營運安排後自動運行。
- 參與方式：突發情況可自行選擇親自玩小遊戲或交給員工；玩家親自處理能得到較高收益。日常能否主動協助，待確認。
- 可參與範圍：排片、賣飛、小食部、清潔。日常排片已確認為時間軸策略介面；小遊戲已選擇短時間操作類型，售票、小食及清潔的個別規則待細化。
- 不同電影類別要有不同客群及收益；已選擇約 6–8 類客群，差異包括電影喜好、到訪時段、小食消費、排隊容忍度及設備要求。分類名稱及具體需求模型待設計。
- 可按電影、時段及格式調整票價，並自行設定各款零食售價。票價提供預設及沿用設定，減少重複操作；介面及價格敏感度待設計。

## 每日經營與成長需求

- 透過每日經營累積資金並升級。
- 裝飾、影院大小、小賣部大小；採指定區域配置設施及裝修風格。
- 音效設備及特別格式影院。
- 承接影展活動及安排特別放映。
- 聘請更多員工，並培訓及分配崗位；系統自動排班。
- 增加食物種類，解鎖後自動供貨，按銷量扣成本。
- 開設更多戲院，重複並擴大經營循環；每間由玩家直接管理，獨立排片、定價及配置員工。
- 租舖起家，再儲錢買斷自己的戲院物業；買斷後免租，仍需維護。具體金額及其他產權細節待確認。
- 已確認成本類別包括租金（租賃期間）、維護費用、票房分帳、員工薪金及按小食銷量扣除的成本；具體金額與結算週期待定。固定片租或保底費未獲選用。

## 核心體驗草案：待使用者確認

經營者透過排片、定價、配置人手與設施，觀察不同客群的選擇，讓戲院自行運作；在突發狀況中決定如何介入，並把盈利投資於更有特色的戲院及分店。

玩家動詞：安排、定價、配置、觀察、判斷、介入、升級、擴張。

暫擬設計支柱：

1. 經營安排有可理解的效果：能從客流、上座率、排隊及收支找出原因；具體介面及公式未定。
2. 自動營運構成主要體驗：不需要反覆手動賣每張票或清理每件垃圾。
3. 電影選擇塑造戲院客群：不同電影的適合客群、時段及設施價值需要存在取捨。
4. 突發介入要與經營連動：玩家可交給員工，親自處理則能得到較高收益；單店一般每日 0–2 次需停下處理的事件，收益影響程度待平衡。

1. 核心節奏：已確認回合制、營業場景可觀察、一日至少 3 分鐘且最終時長待試玩、可加速但不能跳事件、自選短操作小遊戲提高收益、經營有挑戰且可挽救；其餘細節待後續補充。
2. 電影與客群：已確認票房分帳、大片可要求更高分帳且可拒絕放映、約 6–8 類客群、按電影／時段／格式定價、戲仿片名／海報／片商、每週新片與逐步退熱；具體類型及參數待細化。
3. 營運與成長：已確認時間軸排片、個別員工與自動排班、小食自動供貨、區域配置擴建、各分店直接管理、負面事件暫停供玩家補救、租舖再買斷；清潔、維護與各項費用待細化。
4. 表現與原型：已確認電腦瀏覽器、滑鼠操作、等角像素視角及現代香港背景；美術參考、引擎及第一版驗收條件待確認。

## 主要設計風險與待決定事項

- 小遊戲雖可交給員工，但若額外收益過大，可能令玩家覺得必須親自處理，削弱自動經營的目標。
- 需要避免一套排片或價格永遠最優，卻又令收益原因難以理解。
- 臨時下映及維修若缺乏預警或補救，可能只帶來隨機損失。
- 多分店已選擇全部直接管理，操作量可能隨店數增加；可研究玩家主動使用的複製、批次設定及跨店比較工具，不以自動代管取代已確認方向。
- 日長至少 3 分鐘，加上規劃與事件後的單日總遊玩時間需要原型實測；不可用跳事件功能取代觀察或調速。
- 平台、操作方式、美術視角及世界背景已確認；引擎、目標玩家細節及原型規模仍待確認。
